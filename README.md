# PWFramework — Playwright Test Automation Framework

A UI test automation framework built with **Playwright**, **TypeScript**, and **Cucumber (Gherkin/BDD)**, designed around the **Page Object Model** for a demo e-commerce/web application. Includes cross-browser execution, parallel test runs, and CI/CD integration via GitHub Actions.

## 🚀 Key Features

- **Page Object Model (POM)** — clean separation between test logic and page interactions for easy maintenance
- **BDD with Cucumber** — test scenarios written in Gherkin, readable by both technical and non-technical stakeholders
- **Cross-browser testing** — Chromium (Firefox and WebKit available but commented out in config)
- **Parallel execution** — tests run concurrently to reduce overall execution time
- **CI/CD integration** — automated test runs on every push via GitHub Actions
- **Allure reporting** — rich, visual test reports with screenshots on failure
- **TypeScript** — type-safe test code

## ✅ What This Framework Tests

Automated coverage across 3 feature files against a demo web application:
- **login.feature** — authentication/login flow
- **addLocation.feature** — adding a location (job/record creation flow)
- **searchSystemUser.feature** — searching for a system user

## ▶️ Running the Tests

```bash
# Install dependencies
npm install

# Install Playwright browsers
npx playwright install

# Run full suite (clears previous Allure results first)
npm test

# Run tagged subsets
npm run smoke        # tests tagged @smoke
npm run regression   # tests tagged @regression
npm run addLocation  # tests tagged @addLocation

# Generate and open the Allure report
npm run report

# Re-run only previously failed scenarios
npm run rerun
```

## ⚙️ Configuration

- **Tagging strategy**: scenarios tagged `@smoke`, `@regression`, `@addLocation` for selective execution via `cucumber.json`/`package.json` scripts
- **Parallel & cross-browser execution**: configured in `playwright.config.ts`
- **Locators & environment**: centralized in `src/utils/config/locators.json` and `env.ts` for easy maintenance across environments
- **Failed-test rerun**: `@rerun.txt` is auto-generated by Cucumber and consumed by the `rerun` script

## 🔄 CI/CD

Every push triggers the GitHub Actions workflow (`.github/workflows/`), which:
1. Installs dependencies and browsers
2. Runs the full test suite across configured browsers
3. Publishes the Allure report as a build artifact
